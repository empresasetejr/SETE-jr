Desenvolvimento de Projeto Institucional com Chatbot
1. Apresentação da Atividade
Nesta atividade, vocês deverão desenvolver um site institucional completo para uma empresa real, negócio local, projeto comercial pessoal ou iniciativa profissional fictícia com aparência realista.

O objetivo é aplicar, de forma prática, os conhecimentos de HTML, CSS, JavaScript, PHP e MySQL, desenvolvendo uma solução web organizada, funcional e com separação clara entre frontend, backend e banco de dados.

O projeto não será um e-commerce. Portanto, não haverá carrinho de compras, sistema de pagamento ou venda online. A proposta é construir um site institucional, com foco em apresentação do negócio, serviços/produtos e atendimento ao usuário por meio de um chatbot na página de contato.

2. Objetivo Geral
Desenvolver um site institucional para uma empresa, negócio ou projeto comercial, contendo páginas básicas de apresentação e uma área de contato com chatbot funcional, capaz de registrar mensagens em banco de dados e responder ao usuário por meio de IA e/ou fluxo manual de respostas.

3. Objetivos Específicos
Ao final da atividade, a equipe deverá ser capaz de:

Criar uma estrutura básica de site institucional.

Organizar corretamente arquivos HTML, CSS, JavaScript e PHP.

Utilizar boas práticas de separação de responsabilidades no projeto.

Criar uma interface visual coerente com o negócio escolhido.

Implementar uma área de contato com chatbot.

Registrar mensagens do chat em banco de dados MySQL.

Criar respostas automáticas por meio de API de IA e/ou fluxo manual.

Demonstrar domínio básico de frontend, backend e integração com banco de dados.

9. Banco de Dados
O projeto deverá utilizar banco de dados MySQL para armazenar as conversas realizadas no chatbot.

Inicialmente, poderíamos criar apenas uma tabela simples chamada chats, com campos como telefone, origem, mensagem e data. Porém, em um chatbot mais próximo de um sistema real, é importante separar melhor as informações.

Por isso, o projeto deverá trabalhar com uma estrutura simples, mas mais organizada, composta por duas tabelas obrigatórias:

chat_conversations

chat_messages

Além dessas, a equipe poderá utilizar uma terceira tabela recomendada:

chatbot_options

Essa estrutura permite que o sistema armazene não apenas mensagens soltas, mas também conversas completas, com histórico, identificação do visitante e origem de cada mensagem.

9.1 Estrutura geral do banco
O banco de dados deverá conter, no mínimo, as tabelas abaixo:

CREATE DATABASE IF NOT EXISTS devweb_chatbot
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;

USE devweb_chatbot;

CREATE TABLE chat_conversations (
    id INT AUTO_INCREMENT PRIMARY KEY,
    visitor_name VARCHAR(100) NULL,
    visitor_phone VARCHAR(20) NULL,
    visitor_email VARCHAR(150) NULL,
    chatbot_type ENUM('manual', 'ai') NOT NULL DEFAULT 'manual',
    status ENUM('open', 'closed') NOT NULL DEFAULT 'open',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NULL
);

CREATE TABLE chat_messages (
    id INT AUTO_INCREMENT PRIMARY KEY,
    conversation_id INT NOT NULL,
    sender ENUM('user', 'bot', 'ai') NOT NULL,
    message TEXT NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    FOREIGN KEY (conversation_id) REFERENCES chat_conversations(id)
);

CREATE TABLE chatbot_options (
    id INT AUTO_INCREMENT PRIMARY KEY,
    option_number VARCHAR(10) NOT NULL,
    title VARCHAR(100) NOT NULL,
    response TEXT NOT NULL,
    active TINYINT(1) NOT NULL DEFAULT 1
);
9.2 Tabela chat_conversations
A tabela chat_conversations será responsável por armazenar os dados gerais de cada conversa iniciada no chatbot.

Cada vez que um visitante iniciar um atendimento, uma nova conversa poderá ser criada nessa tabela.

CREATE TABLE chat_conversations (
    id INT AUTO_INCREMENT PRIMARY KEY,
    visitor_name VARCHAR(100) NULL,
    visitor_phone VARCHAR(20) NULL,
    visitor_email VARCHAR(150) NULL,
    chatbot_type ENUM('manual', 'ai') NOT NULL DEFAULT 'manual',
    status ENUM('open', 'closed') NOT NULL DEFAULT 'open',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NULL
);
Explicação dos campos
Campo	Descrição
id	Identificador único da conversa
visitor_name	Nome do visitante, quando informado
visitor_phone	Telefone do visitante, quando informado
visitor_email	E-mail do visitante, quando informado
chatbot_type	Tipo de chatbot usado na conversa: manual ou ai
status	Status da conversa: open para aberta ou closed para encerrada
created_at	Data e hora em que a conversa foi iniciada
updated_at	Data e hora da última atualização da conversa
9.3 Tabela chat_messages
A tabela chat_messages será responsável por armazenar todas as mensagens enviadas durante a conversa.

Cada mensagem deverá estar vinculada a uma conversa por meio do campo conversation_id.

CREATE TABLE chat_messages (
    id INT AUTO_INCREMENT PRIMARY KEY,
    conversation_id INT NOT NULL,
    sender ENUM('user', 'bot', 'ai') NOT NULL,
    message TEXT NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    FOREIGN KEY (conversation_id) REFERENCES chat_conversations(id)
);
Explicação dos campos
Campo	Descrição
id	Identificador único da mensagem
conversation_id	Identifica a qual conversa a mensagem pertence
sender	Indica quem enviou a mensagem: user, bot ou ai
message	Conteúdo da mensagem enviada
created_at	Data e hora em que a mensagem foi registrada
Valores possíveis para o campo sender
Valor	Significado
user	Mensagem enviada pelo visitante
bot	Resposta enviada pelo chatbot manual
ai	Resposta gerada pela Inteligência Artificial
Exemplo prático:

conversation_id	sender	message
1	user	Olá
1	bot	Olá! Como posso ajudar? Digite 1 para serviços, 2 para horário ou 3 para localização.
1	user	2
1	bot	Nosso horário de atendimento é de segunda a sexta, das 8h às 18h.
9.4 Tabela recomendada: chatbot_options
A tabela chatbot_options será usada para armazenar as opções do chatbot tradicional, ou seja, o chatbot com respostas prontas.

Essa tabela é recomendada para organizar melhor as respostas, mas a equipe também poderá implementar as respostas manuais diretamente no PHP, usando if, else ou switch.

CREATE TABLE chatbot_options (
    id INT AUTO_INCREMENT PRIMARY KEY,
    option_number VARCHAR(10) NOT NULL,
    title VARCHAR(100) NOT NULL,
    response TEXT NOT NULL,
    active TINYINT(1) NOT NULL DEFAULT 1
);
Explicação dos campos
Campo	Descrição
id	Identificador único da opção
option_number	Número ou código digitado pelo usuário
title	Título da opção
response	Resposta que será enviada pelo chatbot
active	Indica se a opção está ativa ou não
Exemplo de cadastro de respostas prontas:

('3', 'Localização', 'Estamos localizados no centro da cidade. Entre em contato para receber o endereço completo.', 1),
('4', 'Falar com atendente', 'Certo! Informe seu nome e telefone para que um atendente possa retornar o contato.', 1);
9.5 Funcionamento esperado no banco de dados
A equipe deverá registrar no banco de dados tanto as mensagens enviadas pelo visitante quanto as respostas enviadas pelo chatbot.

Exemplo de fluxo:

Usuário acessa a página de contato
        ↓
Sistema cria uma conversa em chat_conversations
        ↓
Usuário envia uma mensagem
        ↓
Mensagem do usuário é salva em chat_messages
        ↓
Sistema gera uma resposta manual ou por IA
        ↓
Resposta do bot ou da IA é salva em chat_messages
        ↓
Resposta é exibida na tela do chatbot
9.6 Chatbot Manual / Chatbot com IA
O projeto deverá conter os dois formatos de chatbot:

Chatbot manual, com respostas prontas e fluxo baseado em opções.

Chatbot com IA, utilizando a API da OpenRouter (Vamos verificar a possibilidade de usarmos uma LLM gratuita pela OpenRouter).

A equipe poderá escolher qual dos dois modos será o principal no site, mas deverá demonstrar que os dois foram implementados.

Em ambos os casos, as mensagens deverão ser armazenadas no banco de dados.

9.7 Exemplo de chatbot manual
No chatbot manual, o sistema poderá exibir uma mensagem inicial como:

Olá! Seja bem-vindo(a). Como posso ajudar?

Digite:
1 - Conhecer nossos serviços
2 - Ver horário de atendimento
3 - Saber nossa localização
4 - Falar com um atendente
Se o usuário digitar 1, o sistema poderá buscar a resposta correspondente na tabela chatbot_options ou tratar diretamente no PHP.

Exemplo usando a tabela chatbot_options:

SELECT response 
FROM chatbot_options 
WHERE option_number = '1' 
AND active = 1;
9.8 Exemplo de chatbot com IA
No chatbot com IA, o fluxo será diferente.

O usuário poderá digitar uma pergunta livre, como:

Quais serviços vocês oferecem?
O PHP deverá enviar essa pergunta para a API da OpenRouter e retornar a resposta gerada pela IA.

Mesmo usando IA, a mensagem do usuário e a resposta da IA deverão ser salvas na tabela chat_messages.

Exemplo:

conversation_id	sender	message
2	user	Quais serviços vocês oferecem?
2	ai	Oferecemos consultoria, atendimento personalizado e suporte especializado.
9.9 Versão simplificada permitida
Será permitido implementar uma versão simplificada do chatbot manual.

Nesse caso, a equipe poderá criar as respostas prontas diretamente no PHP, sem usar a tabela chatbot_options.

Exemplo:

if ($message == "1") {
    $response = "Nossos principais serviços são atendimento personalizado, consultoria e suporte.";
} elseif ($message == "2") {
    $response = "Nosso horário de atendimento é de segunda a sexta, das 8h às 18h.";
} elseif ($message == "3") {
    $response = "Estamos localizados no centro da cidade.";
} else {
    $response = "Desculpe, não entendi. Digite 1, 2 ou 3.";
}
Mesmo nessa versão simplificada, a equipe deverá salvar no banco de dados:

a mensagem enviada pelo usuário;

a resposta enviada pelo bot;

a origem de cada mensagem;

a data e hora do envio.

10. Funcionamento do Chatbot
O chatbot deverá permitir que o visitante envie mensagens e receba respostas automáticas.

O projeto poderá seguir uma das duas abordagens abaixo.

Opção 1 — Chatbot com IA
Nesta opção, o chatbot deverá se conectar a uma API de Inteligência Artificial.

A sugestão para a disciplina será o uso da API da OpenRouter.

O fluxo básico será:

Usuário digita uma mensagem no chatbot.

JavaScript envia a mensagem para o backend em PHP.

PHP salva a mensagem no banco de dados.

PHP envia a mensagem para a API de IA.

A IA retorna uma resposta.

PHP salva a resposta no banco de dados.

JavaScript exibe a resposta na tela.

O chatbot com IA deverá ser orientado ao contexto da empresa escolhida.

Exemplo:

Se o site for de uma clínica odontológica, o chatbot deve responder como atendente da clínica, falando sobre horários, serviços, localização e formas de contato.

Opção 2 — Chatbot Manual com Respostas Prontas
Nesta opção, a equipe deverá criar um fluxo manual de atendimento.

Exemplo:

Olá! Seja bem-vindo(a). Como posso ajudar?

Digite:
1 - Conhecer nossos serviços
2 - Ver horário de atendimento
3 - Falar com um atendente
4 - Saber nossa localização
Exemplo de fluxo:

Usuário: 1

Bot: Nossos principais serviços são:
- Limpeza
- Restauração
- Clareamento
- Avaliação odontológica
O chatbot manual deverá ter lógica baseada na conversa, não apenas uma única resposta fixa para qualquer mensagem.
